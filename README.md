# Прогнозирование рисков ДТП в мегаполисе

Инструмент для пространственно-временного прогнозирования рисков возникновения
дорожно-транспортных происшествий в мегаполисе методами машинного обучения и
геоинформационного анализа. Репозиторий содержит код загрузки и подготовки
открытых данных, конвейер инженерии признаков, процедуру обучения и оценки
моделей, модуль визуализации, модульные тесты и готовые результаты экспериментов.

## Данные

Расчёты выполнены на реальных открытых данных Москвы за 2022--2024 годы:

- дорожно-транспортные происшествия — выгрузка проекта «Карта ДТП»
  (<https://dtp-stat.ru/opendata/>), первоисточник — Госавтоинспекция МВД России;
  координаты, дата и время, тяжесть, число погибших и раненых;
- метеорологические ряды — архив Open-Meteo (ERA5): температура, осадки, ветер,
  облачность, слой снега;
- улично-дорожная сеть — извлечение OpenStreetMap для Москвы: длина дорог,
  число полос, ограничения скорости, покрытие, перекрёстки, объекты притяжения.

Территория покрывается регулярной сеткой 30 × 30 ячеек в границах
55,57–55,92° с. ш. и 37,35–37,90° в. д. Шаг по широте — 0,0117°, по
долготе — 0,0183°, что соответствует примерно 1,30 км с севера на юг и
1,16 км с востока на запад; ячейки прямоугольные, а не квадратные на
местности. Единица наблюдения — «ячейка — сутки»; целевой признак равен
единице, если за сутки в ячейке произошло хотя бы одно происшествие.
Итоговый набор содержит 986 400 наблюдений, 21 912 происшествий и
24 признака; доля положительного класса — 2,17 %.

Погодные ряды описывают фактические условия суток и взяты из архива
реанализа, поэтому результаты относятся к ретроспективной оценке риска.
Для прогноза на следующие сутки вместо архива нужно подставлять прогноз
погоды, доступный в момент расчёта. Извлечение OpenStreetMap получено
24.11.2026 и применяется как статическое описание инфраструктуры для
всего периода 2022–2024 годов.

Синтетический генератор сохранён в `src/nir_pipeline.py` и используется только
как стенд для модульных тестов, то есть для отладки конвейера, а не для обучения
отчётных моделей.

## Результаты

Тестовая выборка — весь 2024 год (329 400 наблюдений, 7 747 положительных).

| Модель | Точность | Полнота | F1 | ROC-AUC | PR-AUC |
|---|---|---|---|---|---|
| Логистическая регрессия | 0,052 | 0,377 | 0,091 | 0,722 | 0,049 |
| Случайный лес | 0,052 | 0,481 | 0,093 | 0,743 | 0,054 |
| LightGBM | 0,068 | 0,257 | 0,107 | 0,750 | 0,057 |
| XGBoost | 0,064 | 0,266 | 0,103 | 0,742 | 0,056 |
| Статистическая модель | 0,049 | 0,390 | 0,087 | 0,681 | 0,043 |

Полные метрики, матрицы ошибок и подобранные гиперпараметры сохранены в
`results.json`, история подбора — в `optuna_history.json`.

Дополнительно проверен вклад групп признаков. Одна инфраструктура даёт
ROC-AUC 0,743 и PR-AUC 0,053; добавление календаря повышает их до 0,750 и
0,057; погодные и лаговые признаки заметного прироста не дают. При
фиксированной доле тревог 5 % LightGBM охватывает 15,6 % опасных
наблюдений, при 10 % — 28,1 %; это больше, чем у остальных моделей.
Результаты сохранены в `extra_results.json`.

## Структура репозитория

```
.
├── src/
│   ├── real_data.py          # загрузка ДТП, погоды и OSM, сборка набора
│   ├── nir_pipeline.py       # очистка, признаки, обучение, оценка, рисунки
│   ├── app.py                # веб-сервис карты риска и прогнозирования
│   ├── extra_experiments.py  # абляции групп признаков и бюджеты тревог
│   └── make_report_figs.py   # перегенерация отдельных рисунков отчёта
├── tests/
│   └── test_pipeline.py      # модульные тесты конвейера
├── fig/                      # готовые рисунки (PDF и PNG)
├── results.json              # метрики моделей и матрицы ошибок
├── extra_results.json        # абляции, бюджеты тревог, важность по gain
├── optuna_history.json       # значения целевой функции по испытаниям Optuna
├── requirements.txt
└── README.md
```

После запуска конвейера в корне также появляются `model.joblib` (обученная
модель LightGBM) и `risk_grids.json` (помесячные карты риска для веб-сервиса).
Каталог `data/` создаётся автоматически: сырые выгрузки складываются в
`data/raw`, промежуточные таблицы — в `data/`. В репозиторий они не включены.

## Установка

Требуется Python 3.10 или новее. Рекомендуется виртуальное окружение:

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
```

## Запуск

Полный конвейер (загрузка данных, обучение, оценка и построение рисунков):

```bash
python src/nir_pipeline.py
```

При первом запуске скачиваются выгрузка ДТП (около 14 МБ) и извлечение
OpenStreetMap (около 163 МБ); дальше используются кешированные файлы.
Скрипт обновляет `results.json`, `optuna_history.json`, `model.joblib`,
`risk_grids.json` и рисунки в `fig/`. Подбор гиперпараметров выполняется на
подвыборке 200 000 наблюдений, всего 25 испытаний.

Веб-сервис карты риска и прогнозирования (после запуска конвейера):

```bash
uvicorn src.app:app --reload
```

Страница `http://127.0.0.1:8000/` позволяет выбрать период и открыть карту,
`/map?period=2024-06` отдаёт карту за месяц, `/predict` принимает вектор из
24 признаков, а `/docs` содержит описание программного интерфейса.

Дополнительные эксперименты к отчёту — абляции групп признаков, важность по
выигрышу функции потерь и сравнение моделей при фиксированной доле тревог:

```bash
python src/extra_experiments.py
```

Скрипт использует уже подобранные гиперпараметры из `results.json`, занимает
около двух минут и записывает `extra_results.json`. Бюджеты тревог задаются
долями 1, 5 и 10 % от тестовой выборки; порог в этом эксперименте не
подбирается, а отсекает заданное число строк с наибольшей оценкой риска.

Перегенерация профиля происшествий, важности признаков и карты риска без
полного обучения:

```bash
python src/make_report_figs.py
```

Каталог для сохранения можно переопределить переменной окружения `FIG_DIR`.

## Методика

- Очистка: проверка диапазонов метеорологических показателей, отбраковка
  записей без координат или с нулевыми координатами, заполнение температуры
  медианой по календарному месяцу, исключение наблюдений с пропуском в целевой
  переменной.
- Пространственные признаки: плотность улично-дорожной сети, число перекрёстков,
  среднее число полос, ограничение скорости, удалённость от центра, плотность
  объектов притяжения, школьная зона, тип покрытия.
- Временные признаки: месяц, день недели, выходные, праздники, зимний сезон,
  циклические составляющие дня года.
- Контекстуальные признаки: температура, осадки, скорость ветра, облачность,
  слой снега, производный признак снегопада.
- Пространственно-временные лаги: происшествия за предыдущие сутки, скользящее
  среднее за неделю, среднее по соседним ячейкам.

Данные разделяются по времени: обучение — январь 2022 — сентябрь 2023,
валидация — IV квартал 2023 года, тест — 2024 год. Порог классификации
подбирается по валидации и фиксируется для теста.
